# Interview Story — Telemetry Privacy Guardrail

**Author: Audrey Rah (Group 7) · Failure-mode package: `student_5_trace`**

Trace events in the orchestrator originally echoed emails, API key material, local filesystem paths, and personal names. That is unacceptable for coursework demos and for any environment that may export spans to a tracing backend such as LangSmith. I added a centralized State Redaction Interceptor that programmatically scrubs secrets, emails, names, and path prefixes before events are written to telemetry storage. On a fixed set of four synthetic events, six sensitive values were detected before redaction; after interception, leaked values fell to zero, yielding one hundred percent measured redaction accuracy on that suite under realistic testing conditions. The before/after table in `metrics.md` is reproducible via `test_failure.py`, demonstrating that privacy controls belong in code at the telemetry boundary rather than in informal logging discipline alone. That six-to-zero leak reduction is the quantified privacy outcome I highlight in professional engineering conversations about production observability.
